# Release 0.3.3 — ADR-0009 typed GillAnswer, and a chart that can pin a digest

Built from tag `0.3.3` on `release-0.3.3` (`a81b98b`), run `39168013081`.

    backend   sha256:2fce1e3467d5f53e4f0700cdd51530db86cc85c8ef7231f091c6e69509b11433
    frontend  built in the same run

**`:latest` moved onto this code and that is accepted, not accidental.** The build
pushed `backend:0.3.3` and `backend:latest` at the **same manifest-list digest**.
Both environments are pinned elsewhere, and the standing rule from 0.3.2 holds:
**`:latest` is never a deploy target, and no acceptance may cite it.** An artefact
that can move under a name cannot witness what was tested.

## What ships

- **ADR-0009 typed `GillAnswer` via BAML**, behind `GILL_STRUCTURED_ANSWER`
  (`b72c0f8`, cherry-picked from `ac71b00`). The flag branches **generation only**:
  quote repair, the Zone-3 sweep, the bookend check and citation validation all run
  unchanged on the rendered prose, so the eval measures the schema change against
  the same verification stack.
- **The chart can express a digest** (`71981b5`). New `goat-yard-archive.image`
  helper: `image.digest` renders `repository@digest`, otherwise `repository:tag`.
  `digest` wins over `tag`, so a pin cannot be defeated by a leftover tag. Three
  refusals — bad prefix, no tag and no digest, no repository — abort the render
  with their own message at the caller's line. **The no-digest path was proved
  inert first**: all four committed values files render byte-identically before
  and after. `charts/test_image_helper.py` holds 10 checks and exits UNRUN
  (status 2) rather than passing when helm is unavailable.
- **`GILL_STRUCTURED_ANSWER` wired into the chart** (`a81b98b`, cherry-picked from
  `b6077f7`): `"0"` in `values.yaml`, `"1"` in `values-test.yaml`.

## Found during the smoke: `/health/stages` alarms on a cold process

Pre-existing, **not introduced here** — `backend/stage_health.py` is byte-identical
to 0.3.2's. Recorded because this deploy is where it was first witnessed.

On a freshly restarted pod, before any request has been served:

    {"stages":{"expansion":false,"entity_lookup":false,"answer":false,"verifier":false},
     "not_observable":[]}

After one request:

    {"stages":{"expansion":true,"entity_lookup":true},"not_observable":["answer","verifier"]}

`public_snapshot`'s own docstring says a stage this build cannot observe "gets NO
boolean and is named here instead", because "false would be an alarm that can never
clear". In the cold window that promise does not hold: `answer` and `verifier` are
reported as `false`. The cause is that unobservability is recorded **per request**
by `main.py`, not derived from the build — so before the first request there is
nothing to move them out of `stages`. **A monitor polling a just-restarted pod sees
two stages alarming that this build can never report on**, which is the precise
failure the third outcome was added to prevent.

## The cold-process health finding is now D-004

The `/health/stages` behaviour below is filed as
[D-004](../defects/D-004-cold-process-stage-health-false-alarm.md) and scheduled
for 0.3.4: `not_observable` derived from the build at startup, with a born-test
that a fresh process serving zero requests raises no false alarm. It was
**observed on production** on 2026-10-25 during the 0.3.2 acceptance, where a
cold pod read every stage false and a second run against the same pod, after one
served request, passed 3/3.

A second conflation on the same endpoint is
[D-005](../defects/D-005-stage-health-conflates-suppression-with-fault.md), also
scheduled for 0.3.4: `false` is additionally returned when a *designed*
suppression fires, and even when a designed recovery succeeds, so it cannot be
read as "this stage faulted".

### Operating rule: nothing alerts on `/health/stages` yet

**Do not point a paging rule, a red dashboard panel or a synthetic check at
`/health/stages` until D-004 and D-005 are both fixed.** A person may read it,
holding the cold-pod caveat. Two independent reasons, each sufficient alone:
every api pod restart opens a window where the endpoint alarms with no fault
behind it and clears only once a request is served (D-004); and `false` covers
designed suppressions and designed recoveries as well as faults, so an alert
would fire on the system working as specified (D-005). The rule lifts when both
born-tests are green against a genuinely cold process -- not when one of them
is. Stated here, and not only in the defect files, because wiring a monitor is a
release-notes-and-runbook decision.


## What this release does NOT solve

- **The gya-test pin is still imperative.** The chart can now hold a digest, but
  `values-test.yaml` does not carry one, and its image value is still `latest`. A
  `helm upgrade` of gya-test still reverts the pin, the debug flag and the
  structured-answer flag in one move. Writing the digest into `values-test.yaml`
  is the obvious next step and was deliberately not taken here: the deployed chart
  is 0.2.1 and an upgrade to 0.3.0 brings far more than the pin.
- **Production is untouched and does not have this code.** Prod never sees
  `ac71b00` until the ratchet holds.
- **The soak measures exposure, not quality.** A week surfaces crashes and
  complaints; the decision still rests on the paired gate run, and `0.3.2`'s
  caveat stands — one replicate pair cannot settle the EFFECT clause.
- The flag is **not a live toggle** (envFrom is read at container start) and is
  release-wide: no canary split, all-or-nothing per namespace.
- `backend/test_structured_answer.py`'s runner still counts its tests dynamically
  with no `EXPECTED_TESTS` assertion.
- D-003 (the retry bound is declared, not observed) is still open, and it is a
  **third** conflation on this endpoint: a stage that succeeded after retries is
  not distinguishable from one that never faltered. D-004, D-005 and D-003 are
  three different causes behind one boolean, which is the shape of the problem
  rather than three unrelated bugs.
- **The endpoint this release line added is not yet usable for the monitoring it
  was built for.** The operating rule above is a standing restriction, not a
  temporary caveat, and it is the honest statement of what `/health/stages` is
  worth today: a thing a person can read, with two defects' worth of context in
  hand.
